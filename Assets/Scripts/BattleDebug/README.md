# 战斗调试台

Unity 顶部菜单 **Dungeon → 战斗调试台**。不需要素材、场景挂件或进入 Play 模式。
第一次打开会创建 `Presets/DefaultBattleDebug.asset` 示例 SO。

## 使用

1. 选择左侧战斗配置。默认是一名勇者对野狼、施毒者，带普通攻击、火球、防御、施毒、治疗和两瓶治疗药水。
2. 输入种子，或点击“取时间种子”，然后点击“开始新战斗”。取时间种子只修改输入框。
3. 每个技能独立选择目标，点击技能按钮。按钮旁显示行动点、资源消耗、冷却和 Core 判定的不可用原因。
4. 点击“结束玩家回合”，再点“单步推进敌人 / 跳过回合”。每次推进一个单位回合，直到回到玩家。
5. 查看各单位生命、法力、护甲、行动点、状态层数、技能冷却及敌人意图；下方日志记录事件和指令前后的数值变化。
6. 逃跑申请后继续推进本轮剩余回合，由 Core 结算结果。战斗结束后可重开。

“原配置 / 原种子重开”使用本场开始时的配置快照，即使左侧 SO 已被改过也不受影响。
要复现相同结果，还需保持 **Core 版本与操作顺序一致**；同一随机种子不会让不同操作产生相同战况。
“开始新战斗”会替换当前调试会话和日志，需要保留时先导出。

## 配置

SO 保存规则、单位、技能、状态、道具和参战单位 ID，不保存本场战斗过程。
修改左侧配置只作用于下一次“开始新战斗”；点击“保存配置”保存资产。
“新建示例配置”创建独立 SO，方便保留多组组合。

- `playerId` / `enemyIds`：引用 units 的 ID；敌人允许重复，实例 ID 自动区分。
- `weapon`：普通攻击对应的技能；`skills`：装备技能及等级、初始冷却。
- `resourceCost` / `actionCost` / `cooldown`：资源消耗、行动点和技能冷却。
- `effects`：效果、目标和数值。数值为 constant + perLevel × 等级；勾选 scaleWithStat 后再加属性 × coefficient。
- `referenceId`：添加状态、召唤、触发技能等效果引用的配置 ID。
- `statuses`：叠层规则、上限、衰减时机、特性和触发效果。状态触发效果的等级取状态层数。
- `deriveAttributes`：启用 Core 的基础属性派生；默认示例关闭，方便直接观察填写的数值。
- `items`：战斗道具及初始数量。最终可用性与目标合法性由 Core 判断，失败原因显示在窗口中。

本工具是独立战斗入口，未走完整 GameRun 的职业、天赋、装备、探索和奖励流程。
调试配置目前覆盖常用战斗字段，不是完整的正式游戏配置编辑器。
整个工具仅编译进 Unity Editor；Core 不依赖 Unity。

## 日志与持久化

- 伤害日志分别显示实际生命伤害和护甲吸收。
- 生命、法力、护甲和行动点事件显示变化后的总值；状态事件显示变化后的层数。
- Core 没有单独发出的资源支付、冷却变化，由指令前后状态对照补充，不能当作逐个效果的中间状态。
- 勾选“原始事件”可查看序号、类型、来源、目标、配置 ID、数值与护甲伤害。
- “复制完整日志”和“导出日志”包含配置快照、种子、输入指令及原始事件。它们是问题排查记录，不是可载入的战斗存档。
- 关闭窗口或脚本重新编译会丢弃内存中的战斗，请先导出需要保留的日志。

按项目要求未添加或执行自动化测试；以 Unity 编译检查确认接入。
